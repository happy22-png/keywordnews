# keywordnews 사용량 최적화

저장소의 index.html을 이 폴더의 index.html로 교체하세요. GitHub 연결의 쓰기 권한 오류(403)로 원격 저장소에는 반영되지 않았습니다.

## 변경 사항

- 페이지 진입, 새로고침, 설정 저장은 API 호출 없이 유효한 저장 결과만 표시합니다.
- 실행 버튼은 같은 키워드·기간·응답 버전의 결과를 30분 동안 재사용합니다. 새 키워드 또는 만료된 결과만 조회합니다.
- 캐시는 현재 브라우저에 최대 50개 검색 조합을 보관합니다. 다른 브라우저나 기기와 공유되지 않습니다.
- 키가 없으면 호출하지 않고 설정을 안내합니다. 실행 중 중복 요청과 설정 변경을 막습니다.
- 실패하면 자동 재시도와 남은 새 요청을 중단합니다. 저장 결과는 계속 표시합니다. 429 응답은 최소 60초 및 Retry-After에 따른 대기를 적용합니다.
- 키워드당 최대 기사 수는 6개에서 4개로, 요약은 두 문장에서 짧은 한 문장으로 줄였습니다. 중복 프롬프트를 제거하고 출력 토큰 상한을 4096으로 설정했습니다.
- 실행별 요청 수, 캐시 재사용 수, API가 보고한 totalTokenCount를 표시합니다. 이 값은 청구서가 아니며 미보고 사용량 및 검색 도구 비용을 포함하지 않습니다.
- 설정 취소 시 키워드를 되돌리고, 키워드와 링크 HTML 처리 및 같은 목록 내 중복 제거를 보완했습니다.

## 검증

Node.js가 있는 환경에서 `node verify.cjs`를 실행하세요. 추가 패키지는 필요 없습니다. 파일 두 개는 같은 폴더에 두세요.

모의 응답으로 자동 호출 방지, 키 누락, 캐시 적중·만료, 새 키워드만 조회, 설정 취소·저장, 중복 실행 방지, 오류 후 중단, 버튼 복구, 429 대기, 중복 제거를 검증했습니다. 실제 Gemini 호출 및 브라우저 시각 검증은 수행하지 않았습니다. 모델과 검색 도구의 실서비스 호환성 및 청구액은 실제 운영 환경에서 확인해야 합니다.

30분 내 같은 조건의 재조회는 API 호출 0회입니다. 기사 수와 요약 길이 축소의 실제 토큰 절감률은 응답에 따라 달라집니다. 여러 기기·사용자 간 요청 통합이나 전체 서비스의 비용 상한이 필요하면 서버 측 캐시와 사용량 제한이 추가로 필요합니다.
